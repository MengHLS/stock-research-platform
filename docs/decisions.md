# 架构决策

仅记录有实际取舍、会影响后续维护的决定。任务进度和测试日志进入 PR/Issue。

## D01 · 单仓库与模块化单体

日期：2026-10-18。状态：采用。

Vue 前端与 Python 后台分目录，API 与 Worker 独立运行但复用后台模块。适合少量用户和前后端接口频繁联动；避免过早承担多仓库同步与服务间通信成本。模块守卫承担结构约束，真正出现独立扩缩容或团队发布需求时再拆服务。

## D02 · 文档和工具数量由检查约束

日期：2026-10-18。状态：采用。

六个正式文档入口，加一个 PR 模板。统一 tools/project.py；临时产物进入 .scratch。检查注册清单和文档长度，避免“再写一个报告/日期脚本”的惯性。

代价是维护者需要编辑现有文档，而非无限追加。真正独立的主题可以经评审调整清单；数量规则不是禁止合理的领域代码或版本化 migration。

## D03 · 认证默认拒绝，开发数据库独立

日期：2026-10-18。状态：采用。

身份尚未接入时不注入管理员。测试使用依赖注入，生产模式启动被阻断。开发 SQLite 用于本地启动和快速契约验证，不能替代目标 MySQL 验证。

旧工程的数据库、账号和历史 Run 没有接入。后续认证库须由 Python 方案重新评估，不沿用此前 Node 后端的 Better Auth 建议作为已定实现。

## D04 · 平台诊断作业先验证调度骨架

日期：2026-10-18。状态：采用。

作业有持久化和租约，但首版只支持短数据库诊断。研究计算在长任务续租、Run 溯源、幂等产物发布和真实算法对拍完成后接入。

旧 Worker 过期后提交会被拒绝；诊断可重试，真实交易或外部副作用不能仅凭这套样板获得“恰好一次”的承诺。

## D05 · OpenAPI 是前后端契约来源

日期：2026-10-18。状态：采用。

FastAPI 生成 schema，固定位置覆盖输出 TypeScript 声明。CI 比较生成结果阻止漂移；不手工维护第二份请求类型，不复制 tRPC 的 Node 运行时到 Python 前端通信层。
