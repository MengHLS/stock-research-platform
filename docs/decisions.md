# 架构决策

仅记录有实际取舍、会影响后续维护的决定。详细任务进度和测试日志进入聊天或 PR/Issue。

## D01 · 单仓库与模块化单体

日期：2026-10-18。状态：采用。

Vue 前端与 Python 后台分目录，API 与 Worker 独立运行但复用后台模块。适合少量用户和前后端接口频繁联动；避免过早承担多仓库同步与服务间通信成本。模块守卫承担结构约束，真正出现独立扩缩容或团队发布需求时再拆服务。

## D02 · 文档和工具数量由检查约束

日期：2026-10-18。状态：采用。

六个工程规范文档入口，另允许用户需求入口 TODO.md、未完成队列 TASKS.md、完成归档 TASKS_DONE.md 和一个 PR 模板。统一 tools/project.py；临时产物进入 .scratch。检查注册清单和文档长度，避免“再写一个报告/日期脚本”的惯性。

用户在 TODO.md 以简短条目记录需求，Agent 细化后加入 TASKS.md 并回填关联 ID；任务规则和未完成队列集中于 TASKS.md，CONTRIBUTING 只保留入口。验收完成的任务及全部关联任务已完成的原始需求移至 TASKS_DONE.md，保留 ID、验收条件与完成证据；仍有依赖或来源引用时按 ID 查询归档，重开时移回活跃文件。AGENTS 指向读取与同步流程。

2026-10-20 按用户要求拆出队列和归档，避免开发规范随待办及历史记录增长。日常仅按需读取活跃任务，归档只在核对完成证据、已完成依赖或重开任务时按 ID 检索；分配新编号使用活跃队列的“下一可用 ID”，避免每次扫描历史。代价是归档时须同步来源关联、编号与证据，不新增逐任务报告。

代价是维护者需要编辑现有文档，而非无限追加。真正独立的主题可以经评审调整清单；数量规则不是禁止合理的领域代码或版本化 migration。

身份尚未接入时不注入管理员。测试使用依赖注入，生产模式启动被阻断。开发 SQLite 用于本地启动和快速契约验证，不能替代目标 MySQL 验证。

旧工程的数据库、账号和历史 Run 没有接入。后续认证库须由 Python 方案重新评估，不沿用此前 Node 后端的 Better Auth 建议作为已定实现。

日期：2026-10-18。状态：采用。

作业有持久化和租约，但首版只支持短数据库诊断。研究计算在长任务续租、Run 溯源、幂等产物发布和真实算法对拍完成后接入。

旧 Worker 过期后提交会被拒绝；诊断可重试，真实交易或外部副作用不能仅凭这套样板获得“恰好一次”的承诺。

## D08 · 一个结果查看器，计算与展示分离

日期：2026-10-18。状态：采用；页面与研究结果契约待实施。

所有实验适配到版本化结果契约，由一个 Vue 查看器展示。图表优先使用与设计系统一致的轻量 SVG；行情复盘总览实测通用图表库的默认表现与原型差距较大且显著增加页面体积，因此不再为简单趋势、热力和 K 线强制引入 ECharts。只有缩放、复杂组合与大规模交互确有必要时再评估专门图表库。首版覆盖分组图、热力图、分面、多维切片与共用明细，不做自由拖拽 BI，也不为每次研究生成独立页面。

代价是计算端需提供可比较的分组结果及合法汇总。查看器不重跑研究、不自行重算权威指标；维度展示、统计限制和验收规则见架构“研究工作流与统一结果展示”。

## D09 · 应用库与研究源分别配置

日期：2026-10-19（初版 2026-10-18，补充 TLS 模式与本机临时豁免）。状态：配置与连接工厂已实现，研究源已连通；只读授权与数据完整性未验收。

应用数据由 API/Worker/Alembic 共用应用连接；研究源使用独立、默认关闭的 MySQL/TiDB 配置。采用分字段凭据、强制加密传输、限时连接及脱敏检查入口。TLS 分三档，前两档强制加密：`verify` 校验证书链与主机名；`verify_ca` 用固定 CA 校验证书链但不校验主机名，等价 MySQL `VERIFY_CA`；`disabled` 为明文，仅限隔离的本机开发。源库只读依赖数据库端 SELECT-only 授权，不把事务声明或连接成功当成权限保证。

`verify_ca` 不是“跳过校验”：它仍强制加密并校验链，校验失败即断连，不降级为不校验连接，与已被明确拒绝的 `prefer` 模式无关。新增它的原因是 MySQL 8 自动生成的服务器证书没有 subjectAltName，本次源库证书无法通过 IP 主机名校验；该服务器在 `disabled` 模式下实测返回 1045，具体认证机制未逐层验证，因此本次采用该模式。2026-10-19 本机实测（临时探针 `.scratch/probe_source_e2e.py` 与 `.scratch/probe_review_http.py`，探针不入库）：`verify` 报 IP 不匹配、`disabled` 报 1045、`verify_ca` 完成认证并经四个复盘接口读到真实数据。探针不在仓库内，复核需按本节重新实测。仅 `verify_ca` 在连接期清掉 Python 3.13 默认开启的 `VERIFY_X509_STRICT`，兼容 MySQL 自动生成证书（参照 PyMySQL 的处理）；默认 `verify` 保留解释器的严格检查。测试在 Python 3.12 主动置位该标志验证两档行为，尚未在 3.13 实测握手。

代价是需分别管理账号和环境；不复制旧库管理员凭据、不自动继承 Node URL。相同库名地址的误配有校验，DNS 别名等须人工确认。模板与接入步骤集中在运维“数据库配置与数据源接入”，本阶段不新增数据库管理页面或采集平台。

本机临时豁免（2026-10-19，用户明确同意，仅限本机开发）：为让研究源先跑通，本机 `.env` 指向旧工程同一个库并使用旧工程的 `app` 账号，实测为 `GRANT ALL PRIVILEGES ON <db>.*`。这违反上文“独立库 + SELECT-only 账号”两条约束，属有意识的临时偏离，不构成架构决定。换库、共享给他人或上线前必须改回独立只读账号并重新核实授权；`tools/project.py db-config` 仍固定输出 `SELECT-only account required; not verified`，工具不因豁免而放松判断。

## D10 · 公共契约以现有技术栈最小落地

日期：2026-10-18。状态：采用；错误分类/脱敏日志/关联标识与前后端超时重试策略已实现，请求层会话失效装配与基础数据类型待实施。

统一错误、关联日志、公共请求与数据类型，沿用 FastAPI、标准 logging、OpenAPI 和 openapi-fetch；不增加通用成功响应包装、另一套 HTTP 库或日志平台。错误映射集中到 `ERROR_SPECS` 显式表（码→状态/类别/安全文案），脱敏集中在 `core/logging.py`，请求上下文用 ContextVar 并在 finally 重置。超时与重试规则集中在 `core/policies.py`，前端 `frontend/src/api/policies.ts` 保留同值表并由测试守护一致：规则形状统一，按 read/write/diagnostic/worker-connect/database-read 分别取不同数值，调用点不写死次数。代价是新错误码必须先登记，未登记的码落兜底 400 并视为评审缺口；超时由持有 I/O 的边界执行，不为统一而用外层定时器包裹阻塞调用。详细契约见架构“公共开发底座”，不在每个模块重复定义。

## D11 · 本地事务足够，并发保护按真实风险添加

日期：2026-10-18。状态：采用；任务幂等/租约样板已存在，其余按场景落实。

少量用户的单体系统暂不需要 Unit of Work、分布式事务、全局锁或事件总线。保留短本地事务、唯一约束和任务条件更新；编辑冲突出现时再启用乐观版本检查。计算与外部 I/O 不占用写事务，数据库与文件发布明确区分。代价是跨资源失败需要显式状态与恢复，不承诺“恰好一次”。

## D12 · 进程统一受控启动与有界退出

日期：2026-10-18。状态：采用；生命周期加固待实施。

本地统一入口管理自己启动的 API/前端进程，API 与 Worker 在部署时分别运行。故障非零退出，先协作停止再限时强停，只清理所属进程组；临时故障有界退避，配置错误快速失败。运行顺序、宽限期与验收见运维“进程生命周期”；长研究执行器未具备停止/租约能力前不注册。

## D13 · 公共行情经统一出站访问，日内数据暂不落库

日期：2026-10-18。状态：采用；腾讯快照/日内K线、新浪竞价成交、东财竞价曲线、Tushare 日线与源状态接口已实现，真实网络/限流验收与冻结快照未完成。

外部行情（腾讯快照与分钟K线、新浪竞价成交、东方财富竞价曲线、Tushare 日线）无鉴权或仅需个人 token、只读且公共，因此不复用研究源数据库连接，也不新增供应商 SDK：统一经 `core/upstream.py` 出站（超时、按源间隔、响应上限、仅 GET 单次重试），失败映射为显式错误码，供应商报文与 token 不进入日志或响应。竞价采用分层取数而非单一来源：成交结果以新浪为主（成交量在全部板块都是精确股数），09:15–09:25 虚拟撮合曲线只有东财提供，东财被反爬拒绝时降级为仅成交并用腾讯分笔兜底，降级状态在响应中显式标记。日内K线与竞价暂不落库，只用进程内 TTL 缓存：当前用途是界面与即时核对，落库会把“未经冻结的时点数据”混进应用库；需要可复现输入时由 datasets 冻结快照并记录版本与抓取时间。

代价是重启后缓存失效、历史日内数据依赖重新抓取；供应商为未公开接口，字段与限流可能变化，必须有解析失败即显式报错而非静默空结果的测试。多来源意味着“同一字段不同源”的口径差异必须在对拍中确认（已确认：分钟线科创板按股、竞价与日线按手，腾讯分笔一律按手），不能假定各源同单位。Tushare 账号权限（竞价、实时分钟需单独开通）与频率限制决定了它现在只做日线对账，不作为竞价或日内来源；不把旧工程的 TUSHARE_TOKEN 自动继承。

## D14 · dev 分支经 GitHub Actions 发布到独立服务器

日期：2026-10-18。状态：编排与流水线已实现；ECS 实际部署与流水线运行待验收。

`dev` 分支承担集成验证，`main` 保持可发布状态，两者走同一套 `tools/project.py check` 门禁。部署链为：推送 `dev` → 质量门禁 → 构建 `api`/`web` 两个不可变镜像（标签为提交 SHA）推送 GHCR → SSH 到 ECS 执行 `deploy/deploy.sh` 拉取并滚动启动 → 远端冒烟。服务器不构建镜像：一是低配机器上编译代价高，二是实测该 ECS 到 Docker Hub 完全不可达、GHCR 可访问，镜像只能在高可用的 Actions 端产出。

数据库复用 ECS 上既有的 MySQL 实例，只新建独立的 `research` 库与 `research` 账号，不启动第二个数据库容器：该机内存 1.6G 且既有 MySQL 已占约 35%，再起一个实例会直接触发 OOM 并加重 swap。应用只连自己的库，不读写既有其他库。只有 `web` 发布端口，`api`/`worker` 仅在既有 MySQL 所在的容器网络内可达。迁移由部署脚本在应用启动前单独执行，容器启动与退出不跑迁移（与 D12 一致）；部署失败按上一版标签自动回滚，状态记录在入库忽略的 `deploy/.state/`。

代价与边界：dev 环境按公网 IP + HTTP 访问，因此只能以 `RP_ENVIRONMENT=development` 与 `RP_AUTH__COOKIE_SECURE=false` 运行——`production` 强制 `cookie_secure=true`，纯 HTTP 下浏览器不回传会话 cookie，登录必然失败。当前 dev 站点**不满足**运维“面向独立服务器的发布门槛”第 3 条（同域 HTTPS），属内部验证环境，不能当作生产发布；接入域名与证书后再切 `production`。镜像仓库改用 GHCR 后不再需要长期保存的仓库密码：CI 用仓库内置 `GITHUB_TOKEN` 推送，部署时经 stdin 在服务器临时登录，凭据随作业失效。

## D15 · 历史复盘首版只读旧源并显式表达缺失

日期：2026-10-18。状态：采用；后端数据底座、Vue 总览与只读下钻已实现，真实源验收待完成。

首版从旧源 `index_daily`、`limit_up_records`、`stock_daily_prices`、`market_data` 读取共享历史复盘数据，通过可替换 `ReviewSource` 接入；旧表不绑定应用 ORM、不做迁移，生产使用独立 SELECT-only 账号。日期上下文、日期摘要、总览和指数四个接口要求登录，但数据不按用户隔离。交易日暂由 `index_daily.tradeDate` 推导并在响应标记来源，因为旧库尚无独立可信交易日历。涨跌停日历的每日家数补充读取同日冻结市场状态：`limitUpCloseCount`/`limitDownCloseCount` 与旧源日期对齐，0 是有效值；冻结源缺失时不回退到其他行情或旧断板数。

覆盖状态只证明“源中存在行”（`presence_only`）。无涨停行、前一日记录缺失、连板链触及有界窗口、个股行情缺失时，对应板数、断板分类、情绪分或涨跌幅为 null 并附稳定 issue；真实零值和失败不得折叠为同一个 0。算法口径固定为 `market-review-v1`，旧公式、旧口径变更须新版本并做固定样本对拍。代价是首版不能宣称历史采集完整。2026-10-20 复核：`index_daily` 四指数各 1888 行（2019-01-02…2026-10-19）、`limit_up_records` 100734 行（同日）、冻结市场状态 1888 行（同日）；`stock_daily_prices` 9041350 行（2018-12-19…2026-10-16）和 `market_data` 232 行（2024-12-31…2026-10-15）沿用上次核对，本次未重算。日期为各表极值，不保证区间内完整，行数随源库增长；只读权限（本机为 D09“本机临时豁免”的全权账号）、数据完整性、查询性能与采集补数仍未验收。

2026-10-21 扩展核心指数为六项：既有上证、深证、沪深300、中证500 继续只读 `index_daily`；`399006.SZ` 创业板指与 `000688.SH` 科创50 先由腾讯公开不复权日线写入应用库 `market_review_index_daily`，复盘再按所选交易日区间读库并与旧源合并。表以 `symbol + trading_day` 为主键，保存 OHLC、`provider` 与 `fetched_at`；刷新按单只和 `RP_REVIEW__INDEX_REFRESH_SECONDS` 判断新旧，重复写入只更新同一主键，不删除库内更早历史。腾讯接口当前最多返回 160 根，实测两指数各有 160 根（2026-02-24…2026-10-20），可覆盖 120 日响应窗口及 MA20 预取；查询日早于库内范围时两只保持 `missing`，不得回退到最新报价。源失败时优先保留并读取库内已有行，只有库内确无对应日期才返回缺失；单只失败不影响另一只或旧源四只；补充源仅提供 OHLC，不伪造成交额或成交量，也不参与旧库交易日历推导。

## D16 · 全球市场概览使用应用库读穿快照

日期：2026-10-20。状态：采用；迁移、多源刷新与降级路径已实现，真实 MySQL 验收待完成。

全球指数页不能把外网可用性当作唯一数据边界：首次请求或超过刷新间隔时读取十项跨市场报价与最多 120 个交易日的日线，成功结果写入应用库；之后优先读库。报价取第一个完整批量源，优先新浪，失败时回退东方财富，最后才逐个调用雅虎，避免为补一个缺口串行放大请求；日线按标的声明候选序列，优先新浪/腾讯/Naver/Yahoo Japan，雅虎仅作后备。历史刷新并发执行并受总同步预算约束；超时先保留已完成结果，报价可先于日线对外读取。单标的缺数据、429 与传输失败均只降级该候选源，不中断其他标的。中韩半导体以 SSE 上市的 `513310` ETF 作为可交易代理，不冒充未持有的 CSI 指数。刷新失败时返回最近成功快照，`stale=true` 并明确提示；单标的缺数据或旧快照在卡片上标记，不用空数据或推算值冒充成功。

该表是界面运行缓存，不是研究数据集，也不改变 D13 对日内 K 线和竞价的限制。它只保存全球概览所需的日线 OHLC 与最新报价；研究需要可复现输入时仍须冻结带版本的数据集。代价是应用库承担少量公共行情行数，并需要部署迁移；删除或重建应用库后必须在首次访问时重新拉取。

## D17 · 回测引擎以旧语义迁移为基线，借鉴 Vibe-Trading 的执行证据

日期：2026-10-21。状态：提案，待用户确认；仅完成实现方案，未授权功能开发，不改变现行架构与研究口径。

依据：HKUDS/Vibe-Trading 固定提交 `fb1851ae1f88943ad9384d132f722e8f9479a027` 的 `agent/backtest/{runner.py,engines/base.py,engines/china_a.py,models.py,metrics.py,validation.py}`；旧工程 `stock-limit-up-analyzer/server/backtest/{engine.ts,execution.ts,marketRules.ts,metrics.ts,backtestResult.ts}`、`server/strategyCore/leakageGuard.ts` 与 canonical 指标对拍测试。旧工程存在大量未提交修改，本次只读工作区内容，实施前须冻结实际文件内容哈希及其依赖，不能仅凭 HEAD 重现。Vibe-Trading 的全量信号输入、结束强平和既有权益分窗不能直接作为防前视、真实成交或样本外验证的依据。

### 范围与模块 Interface

- 首版聚焦单账户、人民币、A 股日线、受控版本化策略；先迁移一条旧策略完整链路，不接期货、期权、实盘、任意上传 Python 或复杂优化器。事件样本收益统计与有限资金账户回测分别标识，前者不得冒充后者。
- 外部 Interface 建议为 `execute(spec, frozen_inputs, control, result_sink) -> summary`：输入只含已授权的不可变版本与显式执行政策；核心禁止网络、数据库、墙上时钟和未声明随机性；错误、取消、资源上限和确定性均属契约。策略只访问截断的 as-of 视图，输出带决策时间和最早成交时间的交易意图。
- `datasets` 提供冻结数据/交易日历及证券历史元信息；`strategies` 管不可变定义、参数和 PIT 守卫；`backtests` 拥有执行循环、委托/成交、账户、唯一指标出口和结果契约；`execution` 管 Job/租约/attempt；`research` 后续管理实验比较。只随纵向能力创建模块，不提前建空包。
- 跨模块通过显式 Interface 和组合根注入；先在 `main.py` 与独立 Worker 组合根接线，更新架构守卫允许明确的契约路径，继续禁止直接引用私有实现或跨模块表。通用存储实现可归 core，core 不依赖业务模块。

### 数据、时序与核算

- `RunSpec` 固定 dataset/strategy 版本、代码与依赖指纹、参数、初始资金、预热/评价窗口、执行/市场/费用/指标/终值政策版本和种子。数据 manifest 固定分片哈希、覆盖、交易日历、证券历史状态、复权/公司行动政策、基准和字段 available_at；缺少关键成交字段拒绝运行，缺少可选分析保留 unavailable。
- 股票池和事件池也有生效/可知时间，保留退市及历史成员，不能按期末存活名单或“后续无连板”等未来标签挑交易。委托明确有效期、受阻后撤销/重试及部分成交残量政策；新首版默认仅下一个交易日开盘有效，未成交余量撤销，持续退出须策略再次发出意图，兼容模式沿用冻结的旧行为。
- 信号可批量预计算，但通过可知性与截断/未来扰动不变性验证后才可复用；默认新策略 T 收盘决策、下一交易日开盘执行。兼容迁移保持旧策略声明的时序，禁止全局 shift 再次延迟。开盘仓位只用当时可知价格，当前日收盘/最高/最低/全天成交量不得参与开盘选股、排序或仓位预算。
- 新政策首版只承诺 NEXT_OPEN 市价委托；止损止盈于收盘确认后排到下一开盘，缺口按实际可成交开盘处理。盘中止损、限价触价及同日止盈止损路径留待独立政策与更细数据，不能从日线推定先后。
- 新执行政策的每日顺序：应用到期公司行动/解锁可卖批次 → 处理此前生成的开盘退出 → 统一预算开仓 → 收盘估值 → 计算下一日意图。稳定标的顺序和明确排名/同分规则保证确定性；现金不足按声明的同比例缩放或排名分配，不能隐含先到先得。兼容政策必须保留所迁移入口的旧订单顺序及逐单资金裁决（旧 Engine 2 按 pending 插入顺序处理，买卖可混排），不能提前采用先卖后买或篮子缩放；这类改进只进入新政策。预检篮子不代表市场保证所有委托一起成交，拒绝/部分成交逐笔记录。
- A 股规则按证券、历史日期和数据版本解析：T+1 使用买入批次可卖数量，不能只看合并持仓首次买入日；涨跌停价、历史 ST/上市阶段、最小交易单位、费用和价格精度均版本化。旧引擎默认不拦截涨跌停必须在兼容政策保留；新增严格政策另立版本，规则缺失不按无限制成交。
- 真实账户用原始交易价格和显式公司行动账；复权序列仅作声明过口径的特征。缺少公司行动时只接收经验证不含行动的样本窗口，不能把复权价格当现金成交。事件 ID 用于信号追溯，经济持仓按证券 ID 汇总，多个事件不能制造多份股票仓位。
- 账户至少有现金、可用/冻结现金、买入批次、总/可卖/冻结股数、已实现损益和费用；所有变动由不可变 Fill/CashFlow 驱动。股票权益为现金总额加持仓市值，手续费只扣一次。申报、费用、舍入与数据缺失政策单独版本化；新政策使用确定小数精度，兼容政策先锁定旧数值及舍入行为。
- 明确 `entry_exit` 与 `target_weight` 两种策略输出，互斥且写入版本；同方向加减仓由执行模式显式控制，不静默丢弃。首条旧策略只迁移其已有模式；目标权重与实际仓位分别发布，后续 target_weight 复用同一成交和账户实现。
- 结束默认按最后可用价格估值并披露陈旧标记及未平仓，不绕过停牌、T+1 或跌停虚构清仓；旧强平规则如需复现仅在兼容政策保留并标识。指标区分已平仓统计和账户总收益；canonical 指标为唯一出口，初始权益、首期费用、年化和无定义值政策一起对拍，不平均分组 Sharpe。

### Run、作业与交付

- 建议按实际需要落表 `dataset_version`、`strategy_version`、`backtest_run`、`backtest_attempt`、`backtest_artifact`；大规模委托/成交/持仓/权益明细放受控产物，应用库保留检索摘要和 manifest。用户标识和所有权从认证服务端确定，运行、计数、对比及产物下载均按用户范围校验。
- 现有 Job 仅支持诊断：启用回测前补全规范化输入摘要（当前仅 job_type 不足）、心跳续租、合作取消、用户配额及 Run/attempt 映射。每个 attempt 独立计算与临时区，不复用未完成账户。只读核心可先通过本地固定样本验证，不提前注册长任务 handler。
- 产物先写 attempt 独占不可变位置并校验完整性；再在应用库短事务中用有效租约、attempt 与 Run 版本条件更新唯一可见 manifest 和成功状态。对象存储不假设支持原子重命名；失租旧 attempt 不得替换可见指针，未发布文件保留待受控清理。取消须确认执行停止，先停再终态，不承诺恰好一次执行。
- 分层缓存为冻结输入、PIT 特征、运行结果；键包含真实依赖版本、参数、时序政策和权限范围。看图/切表只读取已发布结果。公共数据可按授权共享，私人结果不能仅因同哈希跨用户复用。
- 结果包含版本/政策、质量与覆盖、净值/回撤、目标与实际仓位、委托/成交/拒绝原因、费用/换手、未平仓及终值政策。分组研究沿用 D08 约定的统一结果契约，实现待建设的统一运行查看器并增加账户视图，禁止把净值压成分组均值或前端另算权威指标。

### 分期与验收门槛

1. 沿已验证旧 Run 的实际调用链确认迁移入口，不把存在的 Engine 2 当作全部生产执行链；冻结旧策略、数据、参数、依赖及逐笔/权益/指标基线，明确旧行为与新规则差异，先产出能重放的样本与预期。
2. 迁移离线纯核心、PIT 守卫和唯一指标；锁定委托/成交、数量、价格、费用、现金、权益及指标对拍，包含同日买卖混排和多买单争用现金；浮点容差仅用于预先声明的兼容数值，不掩盖交易差异。
3. 补冻结数据与版本元信息、长 Job 生命周期及受控产物发布后，才开放认证提交/查询/取消，并实现 D08 约定的统一 Vue 运行查看器及账户视图；契约生成类型，SQLite 与真实 MySQL 分别验收。
4. 兼容链路验收后另开严格 A 股政策，补历史规则、买入批次、公司行动及目标权重模式；真正 WFA 后续按训练/调参/样本外重跑实现，不用已有权益切窗替代。

每阶段验收覆盖未来扰动/截断不变性、开盘禁读当日未知字段、规则/数据缺失、T+1 加仓批次、停牌与价格限制、资金不足/部分成交、期末未平仓、费用对账、确定性重放；平台阶段另测双用户隔离、重复提交冲突、续租/失租/取消与重试发布竞争。性能按实际样本记录数据量、耗时、峰值内存及缓存命中，不预先承诺秒级全市场；方案审核与代码/真实数据验收分开。
